# סנכרון אנשי קשר · Google ⇄ Microsoft

אפליקציה מינימלית ומאובטחת שמאפשרת לכל משתמש להתחבר לחשבון Google ולחשבון
Microsoft בלחיצת כפתור, ואז לבחור אילו אנשי קשר להעתיק ביניהם — בכל כיוון.

**אין שרת. אין סיסמאות. אין refresh token. אין שמירת נתונים.**

---

## מה זה עושה

1. מתחברים ל‑Google (כפתור) ול‑Microsoft (כפתור).
2. בוחרים כיוון: `Google → Microsoft` או `Microsoft → Google`.
3. לוחצים **תצוגה מקדימה** — האפליקציה קוראת את אנשי הקשר משני הצדדים ומחשבת
   מי **חסר** ביעד (אנשי קשר קיימים לא משוכפלים).
4. מסמנים אילו להעתיק ולוחצים **סנכרון**. האפליקציה יוצרת אותם ביעד ומציגה סיכום.

---

## מודל האבטחה והפרטיות

| עיקרון | איך זה מיושם |
|--------|--------------|
| **ללא שרת** | דף סטטי בלבד. אנשי הקשר עוברים ישירות בין הדפדפן ל‑Google וה‑Microsoft. אף גורם (גם לא אנחנו) לא רואה או שומר אותם. |
| **ללא סוד (secret)** | Google — זרימת token של Google Identity Services. Microsoft — MSAL עם PKCE כלקוח SPA ציבורי. אין client secret בשום מקום. |
| **ללא refresh token** | לא מבקשים `offline_access` מ‑Microsoft, וזרימת ה‑token של Google לא מחזירה כזה. יש רק access token זמני. |
| **תוקף שעה** | הטוקנים נמחקים בהתנתקות, בסגירת הטאב, ולכל היותר **שעה** אחרי החיבור — ואז מתבקשת התחברות מחדש. יש שעון ספירה לאחור בכל כרטיס. |
| **מינימום נתונים** | לא נשמר דבר שאינו נדרש לסנכרון הנוכחי. הטוקן של Google נשמר בזיכרון בלבד; של Microsoft ב‑`sessionStorage` שמתנקה בסגירת הטאב ובנוסף מנוקה מפורשות בהתנתקות/פקיעה. |
| **הרשאות מינימליות** | Google: `openid email` + `contacts`. Microsoft: `User.Read` + `Contacts.ReadWrite`. שום דבר מעבר. |
| **CSP הדוק** | סקריפטים מוגבלים ל‑origin שלכם ול‑SDK של שני הספקים; נתונים יכולים לצאת רק ל‑endpoints של Google/Microsoft. השרת המצורף שולח גם כותרות אבטחה נוספות. |

## למה שני הפורמטים שונים — והמיפוי

לכל ספק מבנה אחר לאיש קשר. האפליקציה ממירה את שניהם ל**פורמט אחיד** ואז חזרה:

| שדה אחיד | Google People API | Microsoft Graph |
|----------|-------------------|-----------------|
| שם פרטי/משפחה | `names[].givenName / familyName` | `givenName` / `surname` |
| שם תצוגה | `names[].displayName` | `displayName` |
| דוא״ל | `emailAddresses[].value` | `emailAddresses[].address` |
| טלפונים | `phoneNumbers[].value` | `businessPhones[]`, `homePhones[]`, `mobilePhone` |
| ארגון/תפקיד | `organizations[].name / title` | `companyName` / `jobTitle` |

ההשוואה בין החשבונות נעשית לפי **כתובת דוא״ל** (ואם אין — לפי שם), כדי לא ליצור
כפילויות.

## התחלה מהירה

הרישום ב‑Google/Microsoft והסבר על **איך להימנע מאזהרות** מפורטים ב‑
**[SETUP.md](SETUP.md)**. בקצרה:

```bash
cp config.example.js config.js   # מלאו שני Client IDs (ראו SETUP.md)
node server.js                   # http://localhost:8000
```

## מבנה הקבצים

```

server.js          שרת סטטי אופציונלי ללא תלויות, עם כותרות אבטחה
SETUP.md           הוראות רישום ב‑Google/Microsoft והימנעות מאזהרות
```

## מגבלות (מכוונות, לשם מינימליות)

- **חד‑כיווני בכל הרצה** — מעתיק את החסרים מהמקור ליעד; להעתקה הדדית מריצים
  פעם בכל כיוון.
- **יצירה בלבד** — אינו מעדכן או מוחק אנשי קשר קיימים, כדי לא לפגוע בנתונים.
- **התאמה לפי דוא״ל/שם** — לא ממזג "כרטיסים כפולים" חכם; המטרה היא סנכרון פשוט ובטוח.
- **פקיעה אחרי שעה** — בהתאם לדרישה: אם לא סיימתם תוך שעה, מתחברים מחדש.
